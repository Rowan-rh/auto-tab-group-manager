# tab-sorting Delta Spec

## Purpose

提供手动触发的标签页排序能力，使分组后的标签条布局确定、整齐：组按标题有序、组内标签有序、无组标签不被打乱、固定标签不受影响。

## ADDED Requirements

### Requirement: 手动触发排序
系统 SHALL 在扩展弹窗中提供"排序标签页"按钮，点击后对所有窗口独立执行排序，并在完成后给出反馈。系统 MUST NOT 在未经用户触发的情况下自动重排标签页。

#### Scenario: 点击按钮触发排序
- **WHEN** 用户点击弹窗中的"排序标签页"按钮
- **THEN** 各窗口标签页按排序规则重新排列，按钮显示完成反馈，标签组列表刷新

### Requirement: 排序规则
系统 SHALL 按以下规则计算每个窗口内非固定标签页的目标顺序：有组标签在前，组与组之间按组标题排序；同一组内按页面标题排序；无组标签位于最后，且保持其原有相对顺序；固定（pinned）标签 MUST 保持原位不参与排序。

#### Scenario: 组按标题有序排列
- **WHEN** 某窗口存在标题为"代码仓库"与"阿里 SLS 日志"的两个组
- **THEN** 排序后"阿里 SLS 日志"组整体位于"代码仓库"组之前，组内标签按页面标题有序

#### Scenario: 无组标签保持原相对顺序
- **WHEN** 窗口中存在若干未分组的标签页
- **THEN** 排序后它们位于所有组之后，且彼此之间的相对顺序与排序前一致

#### Scenario: 固定标签不受影响
- **WHEN** 窗口中存在固定标签页
- **THEN** 排序前后固定标签页的位置不变，且不会被移动到非固定区域

### Requirement: 排序健壮性
排序过程中的标签移动操作 SHALL 复用既有重试机制：遇到"Tabs cannot be edited right now"临时锁时自动重试；单个标签移动失败 MUST NOT 中断整体排序流程。

#### Scenario: 拖动期间排序自动重试
- **WHEN** 排序执行期间用户正在拖动标签页导致移动操作被临时锁定
- **THEN** 系统自动重试移动操作，排序最终完成或安全跳过，不向用户抛出未处理错误
