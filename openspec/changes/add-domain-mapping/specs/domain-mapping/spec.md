# domain-mapping Delta Spec

## Purpose

提供"域名 → 标签组名称"的映射配置能力，让用户可以通过扩展弹窗维护映射规则，使标签页按自定义标签名（而非原始域名）归类分组。

## ADDED Requirements

### Requirement: 映射规则的增删管理
系统 SHALL 在扩展弹窗中提供映射规则的管理界面，允许用户添加"域名 → 标签名"规则、查看已有规则列表、删除已有规则。

#### Scenario: 添加一条映射规则
- **WHEN** 用户在弹窗中填写域名 `code.alibaba-inc.com` 与标签名"代码仓库"并提交
- **THEN** 规则被保存并出现在映射列表中

#### Scenario: 删除一条映射规则
- **WHEN** 用户在映射列表中删除 `code.alibaba-inc.com` 对应的规则
- **THEN** 该规则从列表中移除，后续该域名的标签页恢复按域名分组

#### Scenario: 添加非法输入被拒绝
- **WHEN** 用户提交的域名为空、标签名为空，或域名不是合法的主机名格式
- **THEN** 系统拒绝保存并给出提示，不产生任何规则变更

#### Scenario: 重复域名规则的处理
- **WHEN** 用户为一个已存在映射规则的域名再次添加规则
- **THEN** 系统以新规则覆盖旧规则的标签名，保证同一域名至多对应一条规则

### Requirement: 映射配置的持久化
系统 SHALL 将映射规则持久化保存，使其在浏览器重启、扩展后台服务重启后仍然生效，并随用户账号在 Chrome 登录的设备间同步。

#### Scenario: 重启后配置保留
- **WHEN** 用户保存映射规则后重启浏览器并重新触发标签页分组
- **THEN** 分组行为仍遵循已保存的映射规则

### Requirement: 分组时按映射解析组标题
系统 SHALL 在自动分组与手动整理标签页时，先根据标签页的域名查询映射规则：命中时使用映射的标签名作为组标题；未命中时使用域名本身作为组标题。

#### Scenario: 命中映射的域名按标签名分组
- **WHEN** 已配置 `code.alibaba-inc.com → 代码仓库`，且浏览器中打开多个 `code.alibaba-inc.com` 的标签页
- **THEN** 这些标签页被归入标题为"代码仓库"的标签组

#### Scenario: 未命中映射的域名按域名分组
- **WHEN** 域名 `example.com` 没有任何映射规则，且存在多个该域名的标签页
- **THEN** 这些标签页被归入标题为 `example.com` 的标签组（与现有行为一致）

#### Scenario: 无映射配置时行为不变
- **WHEN** 映射规则列表为空
- **THEN** 所有标签页的分组行为与本变更引入前完全一致

### Requirement: 多域名归入同一标签组
系统 SHALL 允许多个域名映射到同一个标签名，命中同一标签名的不同域名的标签页 MUST 归入同一个标签组。

#### Scenario: 多个域名共享一个标签名
- **WHEN** 已配置 `code.alibaba-inc.com → 代码仓库` 与 `gitlab.example.com → 代码仓库`
- **THEN** 两个域名的标签页归入同一个标题为"代码仓库"的标签组

### Requirement: 策略导出
系统 SHALL 在扩展弹窗中提供导出功能，将当前全部映射规则导出为一个 JSON 文件并触发浏览器下载，文件内容 MUST 能完整还原所有规则。

#### Scenario: 导出全部规则
- **WHEN** 已存在若干映射规则，用户点击"导出"按钮
- **THEN** 浏览器下载一个 JSON 文件，其中包含与当前规则列表一致的"域名 → 标签名"条目

#### Scenario: 无规则时导出
- **WHEN** 映射规则列表为空，用户点击"导出"按钮
- **THEN** 下载的 JSON 文件中规则集合为空，不报错

### Requirement: 策略导入
系统 SHALL 在扩展弹窗中提供导入功能，用户选择本地 JSON 文件后，系统 MUST 校验文件内容的合法性，将其中合法的规则与现有规则合并（同名域名的新标签名覆盖旧标签名）并持久化，非法文件 MUST 被拒绝且不改变现有规则。

#### Scenario: 导入合法文件并合并
- **WHEN** 现有规则为 `a.com → 标签A`，导入文件包含 `a.com → 标签B` 与 `b.com → 标签C`
- **THEN** 导入后规则为 `a.com → 标签B` 与 `b.com → 标签C`，且规则列表即时刷新

#### Scenario: 导入非法文件被拒绝
- **WHEN** 用户选择的文件不是合法 JSON，或结构不符合映射规则格式（如条目缺少域名或标签名）
- **THEN** 系统拒绝导入并给出提示，现有规则保持不变

#### Scenario: 导入文件中的非法条目被过滤
- **WHEN** 导入文件中部分条目域名格式非法或字段为空，其余条目合法
- **THEN** 仅合法条目被导入，非法条目被过滤，并提示实际导入的条目数

### Requirement: 多窗口分组独立性
系统 SHALL 将每个浏览器窗口视为独立的分组域：查找已有组、统计同标题标签页数量、创建与归组操作 MUST 限定在标签页所在窗口内进行，不得跨窗口引用组或合并不同窗口的标签页。

#### Scenario: 多窗口同域名各自成组
- **WHEN** 两个窗口中各有多个相同域名（或同一映射标签）的标签页，触发自动分组或手动整理
- **THEN** 每个窗口内各自生成一个同标题的组，不报错，且不尝试将不同窗口的标签页归入同一个组

#### Scenario: 单窗口内标签页不足不建组
- **WHEN** 某窗口内同标题标签页只有一个，但其他窗口还有同标题标签页
- **THEN** 该窗口内不创建组（数量判断以单窗口为准）

### Requirement: 组颜色稳定性
同一标题的标签组 SHALL 使用稳定的颜色：颜色 MUST 由标题确定，同名组在重建后颜色保持一致，不随创建次序变化。

#### Scenario: 同名组重建后颜色不变
- **WHEN** 标题为"代码仓库"的组被关闭后，因新标签页触发重新创建
- **THEN** 新组的颜色与之前一致

### Requirement: 域名变更时的组归属校正
系统 SHALL 在标签页导航到新的域名后重新解析映射：若标签页当前所在组的标题与其新域名解析出的目标标题不一致，系统 SHALL 将其移出原组并按新标题重新归组。

#### Scenario: 标签页导航后切换组
- **WHEN** 一个位于"代码仓库"组中的标签页导航到了未映射的域名 `news.example.com`
- **THEN** 该标签页被移出"代码仓库"组，并在满足分组条件时归入 `news.example.com` 组
