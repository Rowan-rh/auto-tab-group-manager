## Why

代码审查复现了休眠标签误关闭、后台初始化覆盖活动记录、自动分组并发建组以及操作失败仍显示成功等问题。这些问题会造成用户数据损失或让界面状态与实际结果不一致，需要在继续扩展功能前修复。

## What Changes

- 关闭休眠标签前重新读取标签状态与最近活动时间，跳过确认期间已恢复活动或已变化的标签。
- 合并 session 活动记录与 Chrome `lastAccessed`，始终采用较新的有效时间。
- 等待活动记录初始化完成后再处理激活和关闭事件，避免用不完整快照覆盖 session 存储。
- 按窗口串行执行自动分组，避免并发事件重复创建同一标签组。
- 汇总排序、整理和解散操作中的失败项，并显示完成、部分完成或失败的准确反馈。
- 在保存和导入域名映射时校验标签长度及 `storage.sync` 单项容量，容量超限时保持原数据并提示用户。
- 增加针对上述竞争条件、重新校验和失败传播的回归测试。

## Capabilities

### New Capabilities

- `reliability-safeguards`: 定义活动时间一致性、破坏性操作重新校验、分组串行化、批量操作结果反馈和映射容量保护。

### Modified Capabilities

无。当前仓库尚未将历史 delta 归档到主规格，本变更将相关可靠性约束集中在新能力中。

## Impact

主要影响 `background.js`、`manager.js`、`popup.js`、`common.js` 和 Node 测试。权限、第三方依赖及清单文件无需改变。
