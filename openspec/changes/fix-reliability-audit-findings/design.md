## Context

参见 `proposal.md`。项目是无构建工具的 Manifest V3 扩展，后台 service worker 会被重启，标签事件可能并发到达；管理页的关闭操作在确认前后存在时间窗口。

## Goals / Non-Goals

**Goals:**
- 使用小范围状态协调消除已复现的竞争条件。
- 在执行破坏性操作的最后时刻重新验证条件。
- 让现有弹窗反馈与实际批量结果一致。
- 保持原生 JavaScript、现有权限和零第三方依赖。

**Non-Goals:**
- 不改变域名分组、排序顺序或休眠阈值的产品规则。
- 不引入跨设备活动时间同步。
- 不实现关闭标签的撤销功能。

## Decisions

1. 后台使用一个初始化 Promise 作为活动记录的读写屏障。所有事件先等待加载完成，再修改内存表和持久化，避免维护第二套临时事件日志。
2. 自动分组使用 `windowId` 对应的 Promise 队列。按窗口串行既消除查找与创建之间的竞争，也允许不同窗口并行处理；全局锁会产生不必要的阻塞。
3. 活动时间通过共享纯函数取两个来源的最大有效值。管理页确认后刷新 session 缓存并重新读取候选标签，同时校验激活状态、组和 URL。
4. 批量操作返回计数摘要，由按钮处理器决定完成、部分完成或失败文案。失败保留在控制台，用户界面显示汇总结果。
5. 映射容量按 UTF-8 字节计算，并采用浏览器公开的单项配额值；标签长度设置明确上限，避免单条规则占满存储和破坏布局。

## Risks / Trade-offs

- [确认后重新读取大量标签会增加少量延迟] → 仅对已命中的候选项执行，且在关闭前属于必要校验。
- [按窗口串行可能推迟高频事件] → 队列任务读取当前状态，过期任务安全短路；不同窗口互不阻塞。
- [容量保护会拒绝过去可能尝试保存的大型映射集合] → 现有数据保持不变，并向用户显示明确错误。
